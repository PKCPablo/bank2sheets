## 2026-08-05 — Architecture decision: no formal hexagonal (ADR-0003)

- Reviewed the current implementation against a possible hexagonal/ports-and-adapters refactor; confirmed the informal seams (`TransactionSource`, `HttpExchange`, `GoogleSheetsClient` factory, `Main` as composition root) already deliver the testability and provider-swap flexibility a formal hexagonal would add.
- Recorded ADR-0003: no formal hexagonal architecture; evolve incrementally only on concrete pain (second provider → provider factory keyed by config; pipeline growth → extract use case from `Main`).
- Documented the seams as a deliberate strategy in `architecture.md`.
